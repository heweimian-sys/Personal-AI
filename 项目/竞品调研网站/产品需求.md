# 知行 · 认知加速器 — 产品需求

> 本文档定义产品功能需求，是开发的依据。每次开发前请对照本文档。
> v5 版本

## 一、核心价值

**打通"知道→做到"的信息差链路**：

- 知道：自动搜索、整合、提取信息
- 理解：分析事件间的因果脉络，发现肉眼不可见的趋势
- 做到：输出分角色的行动建议

**核心痛点**：信息有，但脑子进不去。

## 二、信息摄入的心理模型

```
好奇心 → 故事线 → 因果链 → 全局感 → 行动欲
  ↓        ↓        ↓        ↓        ↓
引导语   分章节   连接线   留白消化   总结判断
```

每一步都是一个心理转换，UI 服务于这个节奏。

## 三、用户场景

> 早期产品不泛泛服务"所有想学习的人"，优先服务三类高频任务：创作找角度、工作做研判、探索建认知。

### 场景 1：创作者做选题
> "我想把热点写成一篇有观点的内容"
- 用户：自媒体作者、知识博主、视频策划
- 打开时机：看到热点但不知道怎么切入，或者需要快速补资料
- 典型输入："AI Agent"、"内卷"、"小红书电商"、"美食文化"
- 选择模式：创作
- 输出重点：主题速览、常见叙事、差异化角度、观点冲突、案例证据、内容提纲
- 用户带走：一组可验证的选题角度，而不是一篇直接代写的成稿

### 场景 2：产品/运营做竞品与行业研判
> "我明天要开会，需要先看懂一个行业或竞品"
- 用户：产品经理、运营、创业者、投资/战略实习生
- 打开时机：会议前、立项前、写方案前，需要快速形成初版判断
- 典型输入："OpenAI vs Anthropic"、"低空经济"、"新能源车出海"、"AI 编程工具"
- 选择模式：工作
- 输出重点：执行摘要、市场与趋势、关键参与者、典型案例、风险与待确认问题、会议速记
- 用户带走：可复制到文档或会议材料里的 Markdown/JSON 报告

### 场景 3：个人系统理解一个主题
> "我想真正弄懂这个词背后的脉络"
- 用户：学生、研究者、知识爱好者、AI 工具尝鲜用户
- 打开时机：准备学习新领域，或想把零散信息整理成结构
- 典型输入："唐朝"、"月亮"、"具身智能"、"半导体产业链"
- 选择模式：探索
- 输出重点：一句话认识、核心脉络、关键知识、常见误解、不同视角、继续探索
- 用户带走：一张主题地图和下一步阅读方向

### 场景 4：公开样例报告带来的分享转化
> "我先看到一份报告质量，再输入自己的词"
- 用户：从即刻、小红书、知乎、社群进入的新用户
- 打开时机：看到别人分享的报告截图或链接后产生兴趣
- 典型输入：分享页同类主题或自己的行业/选题
- 选择模式：由样例报告默认带入，也可以手动切换
- 输出重点：清晰标题、来源可信度、知识网络、关键判断、增长钩子
- 用户带走：确认产品能产出有结构的报告，并愿意继续生成或分享

## 四、Phase 1 MVP 功能范围

### 4.1 搜索入口

| 功能 | 说明 | 优先级 |
|---|---|---|
| 关键词输入 | 搜索框 + 示例标签 | 必须 |
| 关键词建议 | 试试：AI行业 \| 新能源 \| 半导体 \| 美食文化 | 必须 |

### 4.2 信息采集与研究

| 功能 | 说明 | 优先级 |
|---|---|---|
| 触发搜索 | 对关键词执行搜索+AI分析 | 必须 |
| Tavily 搜索 | 免费 1000 次/月，专为 AI 设计（优先） | 必须 |
| AI 事件提取 | DeepSeek 提取结构化事件 | 必须 |
| AI 关系分析 | 分析事件间因果关系 | 必须 |
| AI 洞察生成 | 生成趋势判断和行动建议 | 必须 |

### 4.3 阅读式信息流展示

| 功能 | 说明 | 优先级 |
|---|---|---|
| 开头引导摘要 | 2-3 句 AI 摘要卡片 | 必须 |
| 章节式叙事 | 2-4 章节，每章 2-4 事件 | 必须 |
| 因果连接线 | 事件卡片间细线+箭头，标注关系类型 | 必须 |
| 侧边注释 | 右侧 260px 放关联信息、数据来源 | 必须 |
| 留白节奏 | 章节间 120px+ 间距 | 必须 |
| 结尾洞察 | AI 判断 + 分角色行动建议 | 必须 |
| 操作区 | 导出报告、追踪此主题 | 必须 |

### 4.4 响应式设计

| 屏幕 | 布局 |
|---|---|
| ≥1024px | 正文 720px + 右侧侧边注 |
| 768-1024px | 正文 100%，侧边注改为行内注释 |
| <768px | 单列，侧边注消失，连接线简化 |

## 六、数据模型

```python
class Event:
    """信息事件节点"""
    id: str
    title: str                    # "GPT-5 发布，推理速度提升3倍"
    summary: str                  # AI 生成摘要
    date: datetime
    sources: list[Source]         # 引用来源
    confidence: float             # 确信度 0-1
    key_quote: str | None         # 关键引述

class Topic:
    """主题/实体"""
    id: str
    name: str                    # "大模型军备竞赛" / "OpenAI"
    type: str                    # 主题 / 公司 / 人物 / 技术 / 政策
    description: str

class Relation:
    """关联边"""
    id: str
    from_id: str
    to_id: str
    type: str                    # causal / competitive / contains / dependency / chain
    description: str             # "Claude 4 的竞争压力迫使 OpenAI 提前发布 GPT-5"
    confidence: float

class Insight:
    """AI 洞察"""
    id: str
    title: str                   # "模型层战争结束，应用层刚刚开始"
    body: str                    # 详细分析
    judgments: list[str]         # 关键判断
    suggestions: dict[str, list[str]]  # 按角色分组的行动建议
    related_event_ids: list[str]
    related_relation_ids: list[str]

class Report:
    """一次搜索生成的完整报告"""
    id: str
    query: str                   # 用户输入的关键词
    summary: str                 # 开头引导摘要
    chapters: list[Chapter]      # 章节
    events: list[Event]          # 所有事件
    relations: list[Relation]    # 所有关系
    insights: list[Insight]      # 所有洞察
    generated_at: datetime
```

## 八、AI 处理流程

```
用户输入关键词
    │
    ▼
Tavily 搜索 → 获取原始信息列表（降级链：Tavily → Firecrawl → 兜底数据）
    │
    ▼
DeepSeek #1 → 提取结构化事件
  (标题、摘要、日期、来源、关键引述)
    │
    ▼
DeepSeek #2 → 分析事件关联
  (因果关系、竞争关系、包含关系、连锁反应)
    │
    ▼
DeepSeek #3 → 生成洞察和行动建议
  (趋势判断、分角色建议)
    │
    ▼
组装 Report JSON → 返回前端
```
